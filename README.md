# English Portal

Личный портал для изучения английского с нуля до Advanced. Работает офлайн,
без аккаунтов и серверов: весь прогресс хранится в localStorage браузера.

## Запуск

Для разработки:

```bash
npm install
npm run dev
```

Портал откроется на http://localhost:5173

Для ежедневных занятий — собранная версия, она работает офлайн
и ставится как приложение:

```bash
npm start
```

Портал откроется на http://localhost:4173

## Установка на телефон и офлайн

Портал — PWA: после первой загрузки он полностью работает без сети
и ставится на домашний экран как обычное приложение, без магазина
приложений и без запущенного `npm`.

Это не украшение. Интервальные повторения работают только при
ежедневных коротких заходах — если для занятия нужно открыть ноутбук
и поднять сервер, механизм простаивает.

**Как поставить:**

1. Запусти `npm start` и узнай локальный IP компьютера
   (`ipconfig` в Windows, строка IPv4).
2. Открой на телефоне `http://<IP>:4173` — телефон и компьютер должны
   быть в одной сети Wi-Fi.
3. В меню браузера выбери «Установить приложение» или «На экран
   «Домой»».

После установки сервер больше не нужен: всё лежит в кэше телефона.

## Синхронизация между устройствами

Прогресс можно связать между ноутбуком и телефоном через **приватный
GitHub Gist**. Сервер поднимать не надо, аккаунт нужен тот же, что
и для публикации.

**Почему так.** Полноценный бэкенд означал бы сервер, базу и учётные
записи — несоразмерно ради переноса нескольких килобайт между двумя
своими устройствами. File System Access API не подошёл: в мобильных
браузерах его нет, то есть на телефоне он бы просто не работал.

**Подключение.** Заведи токен GitHub с областью `gist` (доступа к коду
и репозиториям такой токен не даёт) и вставь его в «Настройках».
На первом устройстве поле gist оставь пустым — хранилище создастся само
и покажет свой идентификатор. На втором устройстве вставь этот
идентификатор, и портал подтянет прогресс.

**Как сливается прогресс.** Занимаясь на двух устройствах, получаешь две
разошедшиеся истории, и простая перезапись «кто синхронизировался
последним» стёрла бы часть занятий. Поэтому состояния сливаются по полям:

- уроки объединяются — пройденный урок не может стать непройденным;
- по каждому слову побеждает более продвинутая карточка;
- дни занятий объединяются, но один день на двух устройствах остаётся
  одним днём, а не двумя;
- стрик **пересчитывается** по объединённой истории — складывать стрики
  двух устройств бессмысленно;
- счётчики попыток берутся максимумом, а не суммой.

Общий принцип: слияние никогда не завышает прогресс. Там, где честное
значение восстановить нельзя, портал лучше слегка недосчитает, чем
нарисует занятия, которых не было. Слияние состояния с самим собой
обязано ничего не менять — на это есть отдельный тест, иначе каждая
синхронизация накручивала бы прогресс на пустом месте.

**Что уходит наружу.** Только прогресс. Настройки устройства, ключ Claude
и сам токен GitHub в gist не отправляются и в бэкап не попадают.

Синхронизация — единственное, что требует сети помимо проверки письма;
занятия работают офлайн как обычно. Синхронизируйся вручную, когда
пересаживаешься с устройства на устройство.

Учти: `http://` без сертификата работает как PWA только на `localhost`.
Для установки по локальному IP браузер может потребовать HTTPS — поэтому
для телефона надёжнее выложить портал на хостинг (см. ниже).

## Публикация на GitHub Pages

Портал — статика, хостинг бесплатный. После публикации он открывается
с любого устройства по HTTPS, а значит нормально ставится на телефон
как приложение.

Всё уже настроено: в репозитории лежит `.github/workflows/deploy.yml`,
который на каждый пуш в `main` прогоняет тесты, собирает портал
с нужным префиксом пути и публикует. Если тесты падают — публикация
не происходит, опечатка в уроке до сайта не доедет.

**Что нужно сделать один раз:**

```bash
git add -A
git commit -m "English Portal"
gh repo create english-portal --private --source=. --push
```

Затем в настройках репозитория: **Settings → Pages → Source → GitHub
Actions**. После первого запуска портал будет по адресу
`https://<логин>.github.io/english-portal/`.

Репозиторий можно оставить приватным — GitHub Pages в приватном
репозитории доступен на платных тарифах; на бесплатном сделай его
публичным. Ключ API в репозиторий не попадает: он живёт только
в браузере.

**Про подпапку.** GitHub Pages отдаёт проект из `/<имя-репозитория>/`,
а не из корня домена. Это ломает пути к скриптам, иконкам, манифесту
и service worker, поэтому префикс передаётся в сборку через переменную
`PORTAL_BASE`, а манифест и воркер используют пути относительно своей
области действия. Проверить сборку под подпапку локально:

```bash
npm run preview:pages
```

Портал откроется на http://localhost:4174/english-portal/

Если собираешь с префиксом вручную в Git Bash на Windows, учти его
особенность: значение вида `/english-portal/` он превращает
в windows-путь. Используй PowerShell или `npm run preview:pages`.

**Другие хостинги.** Netlify и Cloudflare Pages отдают сайт из корня,
поэтому префикс не нужен — команда сборки `npm run build`, каталог
публикации `dist`.

## Что внутри

**Дорожная карта A0 → C1.** Шесть уровней, 63 урока, 328 упражнений.
Наполнены все:

- **A0** (8 уроков) — алфавит и звуки, приветствия и знакомство,
  местоимения и глагол `to be`, числа и артикли;
- **A1** (12 уроков) — Present Simple с отрицанием, множественное число
  и неисчисляемые, `have got`, вопросы с `do/does` и вопросительными
  словами, предлоги места и времени, `can`;
- **A2** (11 уроков) — Past Simple (правильные, неправильные, `did`),
  Present Continuous и его противопоставление с Simple, `will` и
  `going to`, степени сравнения, `some/any/much/many`;
- **B1** (12 уроков) — Present Perfect и его отличие от Past Simple,
  условные 0 и 1 типа, модальные глаголы (`must/have to/should`,
  `mustn't` против `don't have to`, шкала вероятности), пассивный залог,
  фразовые глаголы;
- **B2** (10 уроков) — Present Perfect Continuous и Past Perfect со сводной
  таблицей всех времён, условные 2 и 3 типа плюс `I wish`, косвенная речь
  с согласованием времён, коллокации и идиомы;
- **C1** (10 уроков) — инверсия после отрицательных наречий и расщеплённые
  предложения, subjunctive и инверсия вместо `if`, модальные глаголы
  о прошлом, хеджирование и вежливая дистанция, академический регистр,
  связки и номинализация.

**Интервальные повторения (SM-2).** Тот же алгоритм, что в Anki. Слово,
которое вспомнилось легко, вернётся нескоро; слово, на котором ты
споткнулся — уже в этой сессии. Это главный механизм портала: именно он,
а не количество пройденных уроков, определяет, останется ли лексика
в памяти.

**Две стороны у каждого слова.** Узнавание (👁 англ. → рус.) и
воспроизведение (✍️ рус. → англ.) — это разные навыки со своими
интервалами. Узнавания хватает, чтобы читать; говорить получается только
когда натренировано воспроизведение. Обратная сторона открывается после
двух успешных узнаваний — вспоминать слово, которое ещё не опознаётся,
бессмысленно. Слово считается выученным, лишь когда обе стороны дожили
до интервала в 21 день.

**Слова открываются уроками.** В повторение попадает только лексика
пройденных уроков — иначе тренажёр подсовывал бы слова из A1 человеку,
который ещё не разобрал алфавит. Слово без контекста запоминается плохо.

**Озвучка.** Через Web Speech API — встроена в браузер, бесплатна и не
требует интернета. На старте слышать слово важнее, чем видеть его.

**Проверка произношения.** Отдельный раздел, где портал слушает тебя
и сравнивает сказанное с образцом — по словам или целым фразам.

Про его границы честно: это не фонетический анализатор. Он не измеряет
качество звуков и не оценивает акцент, а отвечает на один вопрос —
понял ли распознаватель, что ты сказал. Как грубая проверка это
работает: если движок стабильно слышит `sink` вместо `think`,
произношение действительно хромает. Но чистое распознавание ещё
не означает хорошего акцента.

Сравнение намеренно снисходительное к пунктуации и мелким огрехам,
однако порог зависит от длины: на коротком слове одна буква разницы —
это, как правило, другой звук (`three` против `tree`), поэтому там
требуется большее сходство, чем в длинной фразе.

Работает в Chrome и Edge, требует интернета и доступа к микрофону.
В других браузерах раздел показывает понятное объяснение, а остальной
портал продолжает работать полностью.

**Аудирование через диктант.** Отдельный раздел: портал произносит
фразу, ты записываешь услышанное. Фразы берутся из диалогов и примеров
пройденных уроков.

Диктант выбран не случайно. Упражнение с вариантами ответа проверяет
узнавание слова, но связной речи не учит — варианты подсказывают ответ.
Диктант такой подсказки не даёт: приходится расслышать каждое слово,
включая служебные, которые в беглой речи проглатываются и которых
русскоязычное ухо не ждёт.

Разбор идёт по словам и показывает, что именно потерялось. Выравнивание
через наибольшую общую подпоследовательность — иначе один пропущенный
артикль сдвинул бы всё остальное и верный хвост фразы помечался бы
ошибочным. Похожие слова (`think` вместо `sink`) показываются как
замена одной строкой, непохожие — как отдельные потери, чтобы разбор
не превращался в бессмыслицу при ответе мимо.

**Четыре типа упражнений в уроках:** выбор перевода, аудирование,
сборка предложения из слов, ввод перевода. Регистр и знаки препинания
при проверке не учитываются.

## Проверка письма (необязательно, нужен ключ API)

Единственная часть портала, которой нужен интернет. Ты пишешь текст на
заданную тему, Claude разбирает его: исправленный вариант, список ошибок
с объяснениями по-русски и общий комментарий. Задания подобраны по
уровням так, чтобы требовалась ровно та грамматика, которую этот уровень
и разбирает.

Раздел выключен по умолчанию. Без ключа он честно объясняет, чего не
хватает, и ничему не мешает — остальной портал работает полностью
офлайн, как и раньше.

**Подключение:** заведи ключ на `console.anthropic.com`, вставь его
в «Настройках». Запросы идут напрямую в `api.anthropic.com`, модель —
`claude-opus-5`, ответ приходит структурированным JSON по схеме
(`output_config.format`), так что разбор не зависит от того, как модель
отформатировала текст.

**Про безопасность прямо.** Ключ хранится в localStorage браузера
и виден любому, кто откроет консоль разработчика на этой машине. Для
личного портала на своём компьютере это приемлемый размен: альтернатива —
поднимать сервер-прокси, что убило бы офлайн-работу и установку как
приложения. Но:

- не вводи ключ на общем или чужом устройстве;
- не выкладывай собранную версию с ключом в интернет;
- в бэкап прогресса ключ намеренно не попадает — файл бэкапа безопасно
  пересылать и хранить.

Каждая проверка — это платный запрос к API. Ничего не тратится, пока
ключ не введён.

## Как добавить урок

Уроки — это данные, а не код. Открой `src/data/curriculum.js`, найди нужный
юнит и добавь объект в `lessons`:

```js
{
  id: 'a1-u1-l1',           // не менять после первого прохождения:
  title: 'Present Simple',  // по id хранится прогресс
  duration: 15,
  theory: [
    { type: 'p', text: 'Обычный абзац.' },
    { type: 'formula', text: 'подлежащее + глагол + -s', note: 'He works.' },
    { type: 'table', head: ['Лицо', 'Форма'], rows: [['I', 'work'], ['He', 'works']] },
    { type: 'tip',  text: 'Полезный совет.' },
    { type: 'warn', text: 'Частая ошибка.' },
    { type: 'dialog', lines: [['A', 'Do you work?', 'Ты работаешь?']] },
  ],
  vocab: ['work', 'do'],    // id из vocab.js
  exercises: [
    { type: 'choice',    prompt: 'Вопрос?', options: ['а', 'б'], answer: 'а' },
    { type: 'listen',    word: 'work', options: ['work', 'walk'] },
    { type: 'order',     prompt: 'Собери фразу', words: ['I', 'work'], answer: 'I work' },
    { type: 'translate', prompt: 'Переведи: «я работаю»', answer: 'I work' },
  ],
}
```

Новые слова добавляются в `src/data/vocab.js` — обязательны все поля,
иначе тесты не пройдут.

Если добавляешь новый юнит, у пустого юнита должен стоять флаг
`planned: true` — тогда он показывается в дорожной карте как «в разработке»
и не мешает счётчику уроков.

## Тесты

```bash
npm test
```

Проверяют три вещи:

- **математику интервальных повторений** — интервалы, обе стороны
  карточки, правило открытия воспроизведения, локальные даты;
- **целостность контента** — все ли слова уроков существуют, есть ли
  правильный ответ среди вариантов, совпадают ли слова в «собери
  предложение» с ответом, не съехали ли таблицы, не открывается ли
  лексика раньше своего урока;
- **оценку произношения** — насколько снисходительно портал сравнивает
  услышанное с образцом. Слишком строгое сравнение забракует верную
  речь, слишком мягкое — пропустит подмену звука;
- **разбор диктанта** — что выравнивание не сдвигается от пропущенного
  слова и что разбор остаётся учебно осмысленным даже при ответе мимо;
- **слияние прогресса** — что синхронизация ничего не теряет и ничего
  не выдумывает: занятие с другого устройства не должно исчезнуть,
  а повторная синхронизация не должна раздувать счётчики.

Второе особенно полезно — опечатку в новом уроке тест поймает раньше,
чем ты во время занятия.

## Бэкап прогресса

Прогресс живёт в localStorage конкретного браузера. Очистка данных сайта
сотрёт его. В «Настройках» есть кнопки для выгрузки и загрузки JSON-бэкапа —
если занимаешься всерьёз, делай его хотя бы раз в месяц.
